# 우사기 알람시계 설계 문서

- 작성일: 2026-11-16
- 상태: 사용자 최종 검토 대기 (빌더 검토 반영 완료)
- 표기: **[결정]** 사용자가 정한 것 · **[제안]** 설계자(Claude)가 채운 것으로 바꿀 수 있음 · **[빌더]** 구현하는 사람이 정해도 되는 것

---

## 1. 무엇을, 왜 만드나

치이카와의 우사기를 콘셉트로 한 탁상 알람시계다. 알람 시각 몇 분 전부터 "우! 나!" 소리를 1초마다 반복하다가, 정각이 되면 본 알람 노래가 울린다. 설정은 휴대폰 브라우저에서 한다.

- **누가 쓰나 [결정]:** 개인용이다. 두 대를 만들어 사용자와 여자친구가 한 대씩 쓴다. 각자 자기 시계만 설정한다.
- **왜 [결정]:** 둘이 쓰는 개인 물건이면서 **임베디드 개발자 포트폴리오**로도 쓴다. 그래서 "동작한다"에 그치지 않고 설계와 구현 품질을 보여줄 수 있어야 한다.
- **일정 [결정]:** 정해진 마감은 없지만 **2026-12-24 이전 완성**을 목표로 한다. 작성일 기준 약 5주다.

### 목표
1. 시계가 켜져 있으면 알람이 정해진 시각에 **반드시** 울린다. Wi-Fi 장애나 SD카드 문제가 생겨도 마찬가지다. 알람 시각에 전원이 꺼져 있던 경우는 울리지 않아도 된다. **[결정]**
2. "우! 나!" 미리 알림 → 본 알람 → 스누즈/끄기 흐름이 버튼 하나로 자연스럽게 된다.
3. 앱을 설치하지 않고 아이폰 브라우저에서 알람, 소리, 볼륨, 화면 설정을 할 수 있다.
4. 저장소와 문서만 봐도 임베디드 역량이 드러난다. RTOS 작업 설계, 직접 짠 드라이버, 테스트, 신뢰성 처리가 해당된다.

### 비목표 (이번 범위 밖)
- 배터리 구동. 처음에는 USB-C 전원만 쓴다. **[결정]**
- iOS 네이티브 앱, 블루투스 설정. 웹 설정으로 대신한다. **[결정]**
- 외부 인터넷을 통한 원격 설정, 서버, 상대방 시계 설정 **[결정]**
- 앱스토어 배포 **[결정]**
- 조도 센서 자동 밝기, 하드웨어 볼륨 다이얼 **[제안]** 다이얼은 나중을 위해 핀만 남긴다.

### 실패로 간주하는 것 (동작은 해도 안 되는 것)
- 알람을 놓친다. 이게 가장 심각하다.
- 밤에 화면이 너무 밝아서 잠을 방해한다.
- 저장소에 캐릭터 이미지나 음성 같은 저작물이 들어가서 공개 포트폴리오로 쓸 수 없게 된다.
- Arduino 라이브러리를 조립한 수준으로 보인다.

## 2. 제약

- **보드 [결정]:** ESP32 계열, 개발보드에 모듈을 붙이는 방식이다.
- **개발환경 [결정]:** ESP-IDF와 C를 쓴다. Arduino와 Rust는 쓰지 않는다.
- **휴대폰 [결정]:** 두 대 모두 아이폰이다. iOS 사파리는 웹 블루투스를 지원하지 않으므로 웹 설정은 Wi-Fi로만 한다.
- **시간 표시 [결정]:** 12시간제에 AM/PM 글자를 표시한다. 그래서 컬러 LCD를 쓴다.
- **캐릭터 저작권:** 개인용이므로 사용은 괜찮다. 다만 우사기 이미지와 음성은 **펌웨어와 저장소에 넣지 않고** 사용자가 SD카드로 넣는다. 공개 저장소로 포트폴리오를 만들기 위해서다. **[제안]**

## 3. 만드는 방식 (검토한 접근)

| 접근 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. ESP32-S3 + 모듈 + Arduino | 검증된 Arduino 라이브러리 조합 | 가장 빠름 | 포트폴리오에서 "라이브러리 조립"으로 보임 |
| **B. ESP32-S3 + 모듈 + ESP-IDF(C)** | 공식 SDK, FreeRTOS 작업 직접 설계, 드라이버 일부 직접 작성 | 임베디드 기본기가 드러남, 국내 채용 요구(C)와 맞음 | A보다 개발 기간이 김 |
| C. 일체형 보드(M5Stack CoreS3 등) | 화면, 스피커, SD가 보드에 내장 | 배선 없음 | 대당 7~8만 원, 2인치 화면, 탁상시계 케이스에 넣기 어려움, "모듈 조립" 계획과 다름 |

- **선택: B [결정]**
- 처음에는 A를 추천했다. 사용자가 포트폴리오 목적을 밝힌 뒤 B로 바꿨다. 같은 칩이라도 Arduino 결과물은 면접에서 가치가 낮고, ESP-IDF를 쓰면 FreeRTOS, I2S/DMA, 드라이버 작성을 직접 보여줄 수 있다.
- 검토하고 뺀 것:
  - 라즈베리파이: 부팅이 느리고 전원을 뽑을 때 SD카드가 손상될 위험이 있다.
  - STM32: Wi-Fi 칩을 따로 붙여야 한다.
  - Rust: 국내 채용 수요가 적고 MP3/UI 라이브러리가 부족하다.
  - C++: 임베디드 면접에서 감점될 소지가 있다.

## 5. 동작 명세

### 5.1 시간
- 시간대는 한국 표준시(KST, UTC+9, 서머타임 없음)로 고정한다. **[제안]**
- 부팅 순서는 이렇다. **[제안]**
  1. RTC를 읽는다. 값이 유효하면 시스템 시간으로 설정한다.
  2. Wi-Fi를 연결하고 SNTP로 동기화한다.
  3. 동기화에 성공하면 RTC에 시간을 기록한다.
- SNTP는 주기적으로 다시 동기화한다(ESP-IDF 기본 1시간). **[빌더]**
- RTC도 무효이고 네트워크도 없어서 시간을 모르면 화면에 `--:--`와 "시간 설정 필요"를 표시한다. 이 상태에서는 알람을 울리지 않는다. 웹에서 휴대폰 시간으로 수동 설정할 수 있게 한다. **[제안]**
- **꺼져 있던 동안의 알람 [결정]:** 알람 시각에 시계가 꺼져 있었으면(정전, 리셋 포함) 그 알람은 울리지 않는다. 다시 켜진 뒤 지난 알람을 따라잡지 않는다.
- **동작 중 시간 보정 [제안]:** 시계가 켜져 있는 동안 SNTP 보정으로 시간이 몇 초 앞으로 건너뛰면 정각을 "정확히 같은 초"로 비교하는 방식은 알람을 놓친다. 그래서 1초 틱마다 "직전 틱 시각 < 알람 시각 ≤ 현재 시각"으로 판단한다. 건너뛴 폭이 2분 이내일 때만 이렇게 처리하고, 더 크게 건너뛰면 울리지 않는다. 부팅 직후에는 직전 틱이 없으므로 위 [결정]과 자연스럽게 맞는다. `alarm_core` PC 테스트에 넣는다.

### 5.2 알람 항목
알람 개수는 사용자 기준으로 "몇 개든" 등록할 수 있다. **[결정]** 구현상 상한은 32개로 둔다. **[제안]**

| 필드 | 설명 | 기본값 |
|---|---|---|
| 켜기/끄기 | | 켜기 |
| 이름 | 예: "출근" | 빈 값 |
| 시각 | 시:분 (설정 화면도 12시간제 + AM/PM) | |
| 반복 | 한 번만 / 요일 선택(월~일 비트마스크). 매일·평일은 프리셋 | 한 번만 |
| 미리 알림 시간 | 정각 몇 분 전부터 "우! 나!"를 할지. 0이면 미리 알림 없음 **[결정: 소프트웨어로 설정]** | 5분 **[제안]** |
| 미리 알림 소리 | SD카드의 클립 세트 | 기본 세트 |
| 미리 알림 볼륨 | 0~100 | 전역 기본값 |
| 본 알람 노래 | SD카드의 MP3 중 하나 **[제안: 알람마다 선택]** | 첫 번째 곡 |
| 본 알람 볼륨 | 0~100 | 전역 기본값 |

- 0~60분인 미리 알림 범위는 제안이다. **[제안]**
- 한 번만 울리는 알람은 울린 뒤(끄기, 자동 정지 모두) 자동으로 비활성화된다.

### 5.3 알람 한 회차의 흐름 (상태 머신)

```
대기 ──(정각 - 미리알림분)──▶ 미리알림("우! 나!" 1초마다)
미리알림 ──(정각)──▶ 본알람(노래 반복 재생)
미리알림 ──짧게 누름──▶ 미리알림 음소거(소리만 멈춤, 화면 유지) ──(정각)──▶ 본알람
미리알림 ──길게 누름──▶ 회차 종료
본알람 ──짧게 누름──▶ 스누즈 대기 ──(스누즈 분 경과)──▶ 본알람 (미리 알림 없이 바로)
본알람 ──길게 누름──▶ 회차 종료
본알람 ──(자동 정지 시간 경과, 아무도 안 끔)──▶ 회차 종료
스누즈 대기 ──길게 누름──▶ 회차 종료
```

- **버튼 [결정]:** 짧게 누르면 스누즈, 꾹 누르고 있으면 끈다.
- **"꾹"의 기준:** 2초다. 2초에 도달하면 즉시 짧은 확인음을 내고 끈다(손을 떼기 전에). 웹에서 바꿀 수 있다. **[제안]**
- **미리 알림 구간의 짧게 누르기:** "우! 나!"만 멈추고 본 알람은 그대로 울린다. **[제안]**
- **스누즈:** 기본 5분이고 웹에서 바꿀 수 있다. 횟수 제한은 없다. 다시 울릴 때는 본 알람으로 바로 간다. **[제안]**
- **자동 정지 [제안, 검토 후 수정]:** 본 알람이 **아무도 누르지 않은 채 연속으로** 10분 울리면 회차를 종료한다. 스누즈 뒤 다시 울릴 때는 10분을 새로 잰다. 그래서 스누즈를 여러 번 해도 알람이 사라지지 않는다. 웹에서 바꿀 수 있다.
- **"우! 나!" 재생 방식:** 미리 알림 클립 세트는 MP3 클립 1개 이상으로 구성한다. 매 1초 경계마다 다음 클립을 차례로 재생한다. "우" 클립과 "나" 클립을 따로 올리면 "우 → 나 → 우 → 나"가 되고, "우나" 클립 하나만 올리면 매초 "우나"가 된다. 클립이 1초보다 길면 다음 초에서 끊고 다음 클립을 재생한다. **[제안]**
- **겹침:** 한 번에 하나의 "울리는 회차"만 존재한다. 회차가 진행 중일 때 다른 알람의 시작 시점이 오면 그 알람은 현재 회차에 합쳐진다. 길게 누르면 합쳐진 알람이 모두 종료된다. 이미 본 알람 중이면 새 알람은 소리를 바꾸지 않는다. **[제안]**
- **소리 실패 대비:** SD카드가 없거나 파일이 깨졌거나 디코딩에 실패하면 **플래시에 내장된 기본 비프음**으로 대신 울린다. 알람을 놓치지 않는 것이 최우선이다. **[제안]**

### 5.4 화면 (LVGL)
- **평상시 [결정: 12시간제, AM/PM]:** 큰 글씨로 `7:30 AM`, 그 아래 날짜와 요일, 다음 알람 시각, Wi-Fi 상태 아이콘, 캐릭터 이미지 영역을 둔다.
- **미리 알림 중:** 캐릭터 애니메이션과 정각까지 남은 시간을 보여준다. **[제안]**
- **본 알람 중:** 화면을 최대 밝기로 올리고 알람 이름과 애니메이션을 보여준다. "꾹 눌러서 끄기" 안내도 넣는다. **[제안]**
- **캐릭터 이미지:** SD카드 `/images/`에서 읽는다. 없으면 기본 도형/텍스트로 대신한다. 펌웨어에는 넣지 않는다. **[제안]**
- **야간 밝기:** 웹에서 "야간 시간대"(기본 23:00~07:00)와 야간 밝기(기본 10%)를 정한다. 알람이 울리는 동안은 무시한다. 같은 시간대에는 초 표시나 애니메이션을 끈다. **[제안]**
- 화면 레이아웃과 폰트의 세부는 **[빌더]**가 정한다. 폰트는 AM/PM과 숫자가 잘 보이는 굵은 산세리프로 한다.

### 5.5 웹 설정
- **연결 방식 [결정]:** 같은 Wi-Fi 안에서만 접속한다. 외부 인터넷 접속은 하지 않는다.
- **평상시 (집 Wi-Fi):** 시계가 mDNS로 `http://<기기이름>.local`을 띄운다. 두 대가 각자 다른 집에 있지만 이름은 기기마다 다르게 한다(예: `usagi-mj.local`). 처음 설정할 때 정한다. **[제안]**
- **설정 모드 (시계가 직접 Wi-Fi를 띄움):** 저장된 Wi-Fi가 없을 때, 연결이 5분 이상 계속 실패할 때, 또는 버튼을 누른 채 부팅할 때 `Usagi-Setup-XXXX` AP를 띄운다. 접속하면 캡티브 포털로 설정 페이지가 자동으로 열린다. 이 모드에서도 집 Wi-Fi 등록뿐 아니라 알람 설정까지 전부 할 수 있다. AP는 WPA2 비밀번호를 쓰고 비밀번호는 시계 바닥에 붙인다. 집 Wi-Fi에서는 MVP 기준으로 인증 없이 접속한다. **[제안]**
- **설정 모드 동안에도 알람은 계속 동작한다.** 시간은 RTC로 유지한다. **[제안]**
- **공장 초기화:** 버튼을 10초 누른 채 부팅하면 Wi-Fi와 설정을 지운다. SD카드의 파일은 유지한다. **[제안]**

**웹 화면 구성 [제안]:** 아이폰 사파리용 단일 페이지(바닐라 HTML/CSS/JS)이고, 홈 화면에 추가할 수 있다.
- 알람 목록: 추가, 수정, 삭제, 켜기/끄기, "지금 미리 듣기"
- 소리: SD카드 곡과 클립 목록, 업로드(MP3, 파일당 최대 20MB), 삭제, 미리 듣기, 미리 알림 클립 세트 구성
- 설정: 기본 볼륨, 스누즈 분, 길게 누르기 시간, 자동 정지 분, 야간 밝기와 시간대, 기기 이름, Wi-Fi 변경, 시간 수동 설정
- 상태: 현재 시각, 마지막 동기화, Wi-Fi 신호, SD 용량, 펌웨어 버전

**API (JSON over HTTP) [제안]:**
- `GET/PUT /api/settings`
- `GET/POST /api/alarms`, `PUT/DELETE /api/alarms/{id}`
- `GET /api/sounds`, `POST /api/sounds`(스트리밍 업로드), `DELETE /api/sounds/{name}`, `POST /api/sounds/{name}/preview`
- `GET /api/status`, `POST /api/time`(수동 설정), `POST /api/wifi`
- 세부 스키마는 **[빌더]**가 정한다.

### 5.6 저장
- **NVS:** Wi-Fi 정보, 전역 설정, 알람 목록(작은 구조체 배열 또는 직렬화). 전원이 갑자기 끊겨도 깨지지 않아야 한다. **[제안]**
- **플래시 파일시스템(LittleFS 등):** 웹 페이지 정적 파일, 기본 비프음, 기본 폰트 **[빌더]**
- **SD카드:** `/sounds/*.mp3`(노래), `/clips/*.mp3`(미리 알림 클립), `/images/`(캐릭터 그림). 파일명은 업로드할 때 FAT 호환으로 정리한다.
- **파티션:** 2차의 OTA를 위해 **처음부터 OTA 슬롯 두 개**가 있는 파티션 테이블을 쓴다. **[제안]**

## 6. 펌웨어 구조 [제안]

FreeRTOS 작업을 역할별로 나누고 큐와 이벤트로만 통신한다. 알람 판단 로직은 하드웨어와 분리한 순수 C 컴포넌트로 만들어 PC에서 테스트한다.

| 컴포넌트 | 역할 | 비고 |
|---|---|---|
| `alarm_core` | 알람 목록, 다음 울릴 시각 계산, 회차 상태 머신(5.3) | **순수 C, 하드웨어 의존 없음, PC 단위 테스트** |
| `button` | 디바운스, 짧게/길게 누르기 판별 | 판별 로직은 순수 C로 테스트하고, GPIO 인터럽트는 얇게 분리 |
| `ds3231` | RTC 드라이버(I2C) | **직접 작성**(포트폴리오 요소) |
| `timekeeper` | RTC ↔ 시스템 시간 ↔ SNTP 조정 | |
| `audio` | SD/플래시 MP3 디코딩 → 볼륨 조절 → I2S DMA 출력, 비프음 대체 | MP3 디코더 선택은 **[빌더]** (esp-audio-codec, minimp3, helix 등) |
| `display_ui` | LVGL 화면, 백라이트 PWM, 야간 모드 | |
| `net` | Wi-Fi STA/AP 전환, mDNS, 캡티브 포털 DNS | |
| `web` | esp_http_server, REST API, 정적 파일, 업로드 스트리밍 | |
| `storage` | NVS 설정/알람 저장, SD 마운트 | |

- **알람 판단 주기:** 1초마다 판단한다. 미리 알림의 1초 박자는 시스템 시간의 초 경계에 맞춘다.
- **워치독:** 작업 워치독을 켠다. 리셋된 동안 지난 알람은 5.1의 [결정]대로 울리지 않는다. 그래서 리셋 자체가 드물어야 한다. 장시간 시험에서 리셋 횟수와 원인을 기록한다.

## 9. 작업 방식

### 9.1 코드 작성 [결정: 같이, 학습하면서]
사용자가 학습하면서 Claude와 함께 작성한다. 면접에서 사용자가 직접 설명할 수 있어야 한다.

**사용자 배경 (vault 프로필 기준):**
- 철도 신호장치 회사에서 5년 넘게 근무했다. SIL4 소프트웨어 테스트(VectorCAST, 정적·동적 테스트), 회로·PCB 설계, Arduino(C/C++) 펌웨어, TM4C129 MCU 펌웨어 경험이 있다.
- 납땜은 숙련 수준이다. 전자·임베디드기능사가 있다.
- 따라서 새로 배우는 것은 주로 **ESP-IDF API, FreeRTOS 작업 설계, LVGL**이다. C와 하드웨어 기초 설명은 생략한다.
- **통신 기초 보강 [결정]:** 사용자가 SPI, I2C, I2S 지식이 부족하다고 밝혔다. 각 모듈을 처음 붙이는 단계에서 해당 통신의 원리를 먼저 설명하고, 가능하면 로직 분석기로 실제 파형을 보면서 진행한다.
- **DS3231 드라이버는 직접 작성 [결정].** 일정이 크게 밀리면 esp-idf-lib의 `ds3231` 컴포넌트로 바꾸는 것을 대안으로 둔다.

**역할 분담 [제안]:**

| 구분 | 누가 | 대상 |
|---|---|---|
| 사용자가 직접 작성, Claude는 ESP-IDF/FreeRTOS 개념 설명과 리뷰 | 사용자 | `alarm_core`, `ds3231`, `button`, FreeRTOS 작업/큐 구성, `audio`(I2S DMA, 볼륨, 디코더 연결), `timekeeper`, `storage`, `net` |
| Claude가 작성하고 사용자가 읽고 설명을 들음 | Claude | 빌드/CMake 뼈대, LVGL 초기화와 화면 배치, 웹 페이지(HTML/CSS/JS), CI 설정, 케이스 모델 |
| 같이 작성 | 둘 다 | HTTP 핸들러와 API, 캡티브 포털, 웹 펌웨어 업데이트 |

- 단계마다 "개념 설명 → 사용자가 작성 → 테스트/실기 확인 → 리뷰" 순서로 진행한다.
- **사용자 강점을 살린 포트폴리오 요소 [제안]:** SIL4 테스트 경험과 연결해 CI에 정적 분석(cppcheck)과 `alarm_core` 테스트 커버리지 측정을 넣는다. 전용 PCB(KiCad)는 사용자의 PCB 설계 경험과 이어지지만 한참 뒤로 미룬다.
- **가용 시간 [결정]:** 주당 많이 투입할 수 있다. 8장 일정을 그대로 목표로 삼는다. 1차 필수 범위는 크리스마스 전에 가능하다고 본다.

### 9.2 장비
- **인두, 멀티미터 [결정]:** 지인에게 빌린다. 2주차 브레드보드 조립 전에 확보한다.
- **추가로 필요한 것 [제안]:**
  - 브레드보드, 점퍼선(듀폰), 핀헤더
  - 디지털 캘리퍼스: 케이스 모델링용 실측에 필수. 1~2만 원이거나 빌린다.
  - (선택) 저가 로직 분석기(8채널, 1만 원 안팎): SPI/I2C/I2S 파형을 확인하는 디버깅용. 캡처 화면은 포트폴리오 자료로도 쓸 수 있다.

### 9.3 케이스 [결정: 주문 제작]
- **모델링은 Claude가 한다 [결정].** OpenSCAD나 CadQuery(Python)처럼 코드로 쓰는 파라메트릭 모델로 만든다. 치수를 바꾸면 다시 생성할 수 있고 저장소에 함께 올라가서 포트폴리오에도 들어간다. **[제안]**
- **출력은 사용자가 국내 3D 출력 대행 업체를 찾아 맡긴다 [결정].** 업체 조사는 모델링 단계에서 같이 한다.
- **치수 확보:** 부품이 도착하면 캘리퍼스로 실측한다(화면 모듈, 보드, 스피커, 버튼, USB-C 위치). 데이터시트 치수만 믿고 모델링하지 않는다. **[제안]**
- **출력 전 확인:** 보내기 전에 미리보기 이미지를 만들어 사용자가 형태를 확인한다. 가능하면 1차 출력을 1대분만 먼저 맡겨서 맞춰본 뒤 2대분을 맡긴다. **[제안]**
- **형태:** 평범한 탁상 알람시계 모양, 앞면 화면, **윗면 스누즈 바**, 뒷면 USB-C와 스피커 구멍 **[결정 + 제안]**. 스누즈 바는 바 전체 어디를 눌러도 아래 마이크로 스위치가 눌리도록 가이드를 두고, 1대분 시험 출력으로 걸림과 눌림 깊이를 맞춘다. 재질(FDM PLA/PETG 또는 레진)은 견적을 보고 정한다.
- **일정 영향:** 출력 대행은 견적부터 배송까지 보통 1주 안팎이 걸린다. 그래서 모델링은 부품 실측 직후(2주차)에 시작해서 3주차 안에 주문한다. **[제안]**
